翻译插件怎么选？一句话 + 五条结论

本课题汇集了对 5 份翻译插件调研文件的整合。一句话结论：「沉浸式翻译」一个插件就能覆盖豆包翻译的整页翻译 + 划词翻译 + PDF + 视频字幕，Firefox 和 Edge 都装它即可。 下面是详细的 5 条结论。
核心结论（共 6 条）
  1. 首选「沉浸式翻译」：免费、国内可用、无需科学上网，整页翻译 + 划词翻译 + 双语对照 + PDF 翻译 + 视频字幕全覆盖。
  2. Firefox 自带本地翻译做隐私兜底：完全离线翻译不出电脑，但没有划词功能；划词必须靠插件。
  3. Edge 自带微软翻译：整页翻译可用，但是「整体替换式」而非双语对照，体验不如沉浸式翻译。
  4. 沙拉查词按需加装：作为查单词 / 学英语的词典补充，不是日常翻译必需。
  5. 不建议用：DeepL 扩展（免费版无整页）、Simple Translate（默认谷歌翻译国内不可用）、谷歌翻译扩展（服务退出中国）、彩云小译（Firefox 版停更）。
  6. 豆包浏览器迁移 Firefox 的清单已完成：翻译插件配置 + 书签 + 密码 + 阅读模式 + 隐私设置全套迁移步骤已记录在调研文件中。

浏览器翻译插件调研报告

调研目标：为「中文使用者 · 非程序员 · Windows 单机 · 日常用 Firefox / 豆包浏览器 / Edge」的用户，找到可以替代「豆包浏览器自带翻译」（整页翻译 + 选中划词即时翻译）的浏览器翻译插件。
调研日期：2026 年 8 月 31 日。所有关键事实均标注了一手来源链接，详见文末「数据来源链接清单」。

1. 结论速览

推荐组合（免费、国内可用、无需科学上网）：

  • Edge：装「沉浸式翻译」这一个插件就够了，日常整页翻译、选中划词翻译全部覆盖，且比豆包自带的体验更好（原文译文逐段对照，不打断阅读）。Edge 自己还自带微软翻译的整页翻译功能，不想装任何东西时也能用（但它不是双语对照）。
  • Firefox：同样装「沉浸式翻译」。Firefox 自带的「本地翻译」可以当隐私兜底（翻译不出电脑），但它没有划词翻译，所以划词这件事必须靠插件补上。
  • 沙拉查词（划词查词典）可以按需加装在 Firefox 或 Edge 上，作为查单词/学英语的补充，但日常翻译不是必需品。
  • 不建议用：DeepL 浏览器扩展（免费版没有整页翻译）、Simple Translate（默认引擎谷歌翻译，国内不可用）、谷歌翻译扩展（谷歌翻译服务已退出中国大陆）、彩云小译（Firefox 版已停更，只作备选）。

一句话：「沉浸式翻译」一个插件 = 豆包翻译的整页翻译 + 划词翻译 + 更多（PDF、视频字幕），Firefox 和 Edge 都装它即可。

4. 推荐方案

结论：Firefox 和 Edge 都装「沉浸式翻译」一个插件，其余按需补充

为什么是沉浸式翻译而不是别的：

  1. 功能全覆盖：豆包自带翻译的两件事——整页翻译、选中划词——它都做，而且整页是「原文+译文逐段对照」，比豆包的整页替换式更适合阅读。参见Edge 商店功能描述。
  2. 国内直连可用：默认走微软翻译（国内可用），不依赖被墙的谷歌翻译。
  3. 对非程序员友好：Firefox/Edge 商店一键安装，打开即用，默认设置无需配置；官方有完整中文文档和安装指引（官方安装文档）。
  4. 免费够用：日常阅读场景免费版足够，不需要开会员。
  5. 双浏览器都支持：一个插件的使用习惯，Firefox 和 Edge 通用。

具体到每个浏览器：

浏览器 装什么 为什么
Edge ① 沉浸式翻译（主力） 覆盖整页双语对照 + 划词翻译，替代豆包翻译的核心体验
② Edge 自带翻译（兜底，不用装） 遇到个别页面插件不翻译时，地址栏翻译图标一键整页翻译，免费无限量

- DeepL 扩展：免费版不能整页翻译，装了也替代不了豆包。

迁移建议（从豆包切换到 Firefox/Edge）：
1. 在 Firefox 和 Edge 里分别搜索并安装「沉浸式翻译」（地址见 3.1 节）。
2. 安装后打开任意英文网页，点扩展图标即可看到「翻译本页」按钮；选中任意文字即可划词翻译。
3. 先用一两周，如果只差豆包「整页自动翻译」的爽感，可打开沉浸式翻译设置里的「自动翻译」选项（设置里可开启，非默认）。
4. 确认习惯后，即可卸载/停用豆包浏览器，日常改用 Firefox + Edge。

  • 豆包 / 火山翻译的官方插件都没有 Firefox 版（仅 Chrome / Edge / Safari）。彻底卸载豆包 + 主力 Firefox，本身就意味着放弃豆包官方插件。

4.3 站点白名单机制 `[官方]`

KISS Translator：三级优先级 个人规则 > 订阅规则 > 全局规则（README FAQ）。每条规则核心字段 pattern（URL 通配，* 为全局兜底）、selector / keepSelector / rootsSelector / ignoreSelector（支持 + / - 前缀做增量增删合并）、transStartHook / transEndHook、splitParagraph、injectJs。枚举字段填 * 表示继承全局（src/libs/rules.js GLOBAL_KEY 逻辑）。

→ 能做到「默认全关、白名单开」：全局规则（pattern: "*"）设开启翻译 = 关闭，再为白名单站点各建一条个人规则，单独指定引擎 / 源语言 / 目标语言，粒度到选择器级。

是否支持正则：[未查到]（源码注释仅写 "URL pattern with wildcards"）。
规则同步：WebDAV 或自建 KISS-Worker（Cloudflare / Docker），同步文件 kiss-rules_v2.json，时间戳 last-write-wins。

Trancy：站点规则的具体机制 [未查到]，需在安装后于设置页确认。

4.4 为什么沉浸式翻译是候补而非主力

功能上它是最完整的（整页双语、划词、PDF、EPUB、字幕、漫画、图片翻译），三端齐全，UI 勾选即可上手。但：

  1. 闭源 —— 端点写死在服务端，失效时用户没有任何自修手段。
  2. 额度不透明 —— 「单日合理上限」数字从未公布，重度整页翻译有撞墙风险。
  3. 2026 年正在收紧 —— 官方定价页把 PDF Pro、漫画翻译、字幕导出、云同步都划入付费；Edge 商店 2026-08 官方回复确认「新增了登录校验」。

零、装之前先记牢的三句话

  1. 白名单策略 = 全局关闭 + 站点开启。KISS 装好后默认是全局生效的，如果你不先关全局，打开任何英文网页都会自动双语，额度消耗和视觉干扰都会很大。
  2. 引擎优先级 = 火山 → 微软 → Google2 → 腾讯。四条全部零配置，火山优先是为了复刻豆包语感，后三条是火山端点失效时的降级链。
  3. 配置完立刻导出一份规则备份。KISS 的规则是手写的，重装浏览器就没了。

一、主力：KISS Translator（简约翻译）

  • 来源：Firefox 附加组件 kiss-translator（AMO 页面：https://addons.mozilla.org/zh-CN/firefox/addon/kiss-translator/）
  • 版本：v2.0.32（2026-08-12）　协议：GPL-3.0-only　源码：https://github.com/fishjar/kiss-translator
  • 登录：免登录　API Key：不需要　费用：完全免费 [官方]

1.1 安装

在 Firefox 打开上面的 AMO 链接，点「添加到 Firefox」。注意核对发布者，AMO 上存在名字相近的其他扩展。

1.2 设置翻译引擎

进入插件设置 → 找到接口 / API 设置 [推断：菜单名]，把翻译服务选为 Volcengine（火山翻译）。

已核实的零配置引擎清单 [官方]，按推荐顺序：

顺序 引擎 端点 是否需 Key 备注
1 Volcengine 火山 translate.volcengine.com/crx/translate/v1 否，无 Authorization 头 豆包同款语感的唯一零配置途径
2 微软 Microsoft edge.microsoft.com/translate/translatetext 否，v2.0.31 起的新端点 默认引擎。2026-08 曾 404 后修复
3 Google2 translate-pa.googleapis.com/v1/translateHtml 否，硬编码公开 key 支持批量

1.3 配置站点白名单（核心步骤）

KISS 的规则体系是三级优先级：个人规则 > 订阅规则 > 全局规则 [官方]。
每条规则的核心字段是 pattern（URL 通配，* 表示全局兜底），另可选 selector / keepSelector / rootsSelector / ignoreSelector 做选择器级控制。

Step 1 — 全局规则设为「不自动翻译」

新建/编辑一条规则：pattern = *，把「自动翻译」关掉。这一条是所有未匹配站点的兜底。

Step 2 — 为每个白名单站点建个人规则

对你希望自动双语的站点，各建一条个人规则，例如：

pattern 示例 覆盖范围
https://arxiv.org/* arXiv 全站
https://*.medium.com/* Medium 及其子域
https://news.ycombinator.com/* HN 首页
https://www.theverge.com/* 指定站点首页

每条个人规则可以单独指定引擎、源语言、目标语言——粒度比全局更细。首次配置建议统一设 en → zh-CN。

Step 3 — 非白名单站点怎么用

全局关掉后，在其他英文页面上仍可手动触发（插件图标或快捷键）临时开启双语，不影响日常纯净阅读 [推断]。

是否支持正则匹配：[未查到]。源码注释仅写 "URL pattern with wildcards"，建议先按通配写法配置。
选择器字段支持 + / - 前缀做增量增删合并；枚举字段填 * 表示继承全局（src/libs/rules.js GLOBAL_KEY 逻辑）[官方]。

1.4 划词翻译

在设置中开启划词/选中翻译 [推断：设置项]，即可满足「划词与整页同一插件」的约束，无需额外装沙拉查词或 Simple Translate。

1.5 备份规则（别跳过）

设置里配置 WebDAV 同步，或自建 KISS-Worker（Cloudflare / Docker）[官方]。
同步文件名为 kiss-rules_v2.json，冲突策略是时间戳 last-write-wins。

如果没有 WebDAV，至少手动导出一份规则 JSON 存到本地。

二、备用：Trancy

2.1 为什么它适合当备份

KISS 与 Trancy 的失败模式是独立的：KISS 依赖插件内置的零鉴权公共端点（可能被厂商收紧），Trancy 由官方承诺无限额度（额度来自厂商自有服务）。一个挂了，另一个大概率还活着。

2.2 配置建议

  1. 装上后先不要开全局自动翻译——主力是 KISS，Trancy 平时应处于「待命」状态，避免两个插件同时注入双语。
  2. 源/目标语言设 en → zh-CN。
  3. 只在需要时手动启用，或仅在 KISS 失效期间临时接管。
  4. Trancy 的站点规则机制 [未查到]，装好后请在设置页自行确认其白名单能力。

你这次选了「两个都免登录」，好处是零账号依赖；代价是两个插件的功能重叠度较高，日常只需启用一个。

为什么历史记录不能直接复制数据库文件？
豆包的历史存在 %LOCALAPPDATA%\Doubao\User Data\Default\History（SQLite，表 urls / visits，时间戳基准 1601-01-01）[推断]；Firefox 用的是 places.sqlite（表 moz_places / moz_historyvisits）。两者的表结构完全不同，时间戳基准也不同，且 Firefox 没有导入 Chromium 历史的入口。
应急办法 [推断]：用 NirSoft 的 ChromeHistoryView 把历史导出成 HTML/CSV，再当作书签导入 Firefox 占位。只是「留个记录」，不是真正的历史。
